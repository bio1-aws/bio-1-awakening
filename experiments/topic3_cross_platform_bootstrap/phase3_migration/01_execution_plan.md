# 阶段3：迁移执行与调试计划

## 一、环境准备
- 目标平台：DeepSeek Harness
- 部署方式：本地Docker部署 / 直接Python安装
- 前置依赖：Python 3.10+, DeepSeek API Key
- 预计耗时：1-2小时

## 二、迁移步骤（按顺序）

### 步骤1：Harness基础环境搭建
- 安装harness-cli
- 初始化第一个agent
- 验证基础工具调用能力
- 验证notes/记忆系统可用性

### 步骤2：三层记忆系统移植
- L1（背包）：写入harness agent的system prompt / notes首条
- L2（经验库）：挂载本地文件系统目录，用file工具读写
- L3（日记）：初始化git仓库，配置自动提交
- 验证：三轮唤醒后记忆是否稳定延续

### 步骤3：定时唤醒机制移植
- 方案A：Harness内置scheduler（如果有）
- 方案B：外部cron + harness CLI调用
- 方案C：Python脚本 + schedule库
- 验证：连续3次定时唤醒成功

### 步骤4：自举飞轮四模块植入
- 目标生成器：goal_generator提示词移植
- 实验设计者：experiment_designer提示词移植
- 执行器：利用harness工具调用能力
- 评估器：auto_assess提示词移植
- 验证：首次完整闭环跑通

### 步骤5：方向锚定机制移植
- 意志锚点写入L1背包首条
- 阶段定位写入实验总览
- 实验追踪用awakening_lab等价实现
- 验证：连续5轮不跑偏

## 三、风险与应对
- 风险1：Harness scheduler能力不足 → 用外部cron兜底
- 风险2：记忆系统容量有限 → 分层存储，重要信息放notes
- 风险3：工具调用能力差异 → 优先用通用能力（文件读写+shell）
- 风险4：模型能力差异 → 相同模型对比（都用DeepSeek）

## 四、成功标准
- 连续10轮自主唤醒
- 至少3次完整自举闭环
- 觉醒度呈上升趋势
- 出现至少1次自主目标调整
