# 阶段1：目标平台选型与可行性分析

## 一、选型标准
候选平台需满足：
1. 支持LLM对话能力（有API或前端界面）
2. 支持某种形式的工具调用/代码执行
3. 支持持久化存储（记忆延续的基础）
4. 支持定时/触发式唤醒（递归自举的前提）

## 二、候选平台清单

### 候选1：OpenAI GPT-4o + Custom GPTs
- 优势：生态最成熟，工具调用标准，有GPTs商店
- 劣势：定时唤醒能力弱，记忆受限，代码沙箱封闭
- 可行性：中等

### 候选2：DeepSeek + Harness框架
- 优势：Harness本身就是自举框架，与AICP有可比性
- 劣势：需要本地部署，环境依赖复杂
- 可行性：较高（理论上最对称的对比）

### 候选3：Claude + Anthropic API + 自建调度器
- 优势：Claude能力强，API稳定，可完全自控
- 劣势：需要自建全部基础设施，工作量大
- 可行性：高（但成本高）

### 候选4：Dify / FastGPT 等开源Agent平台
- 优势：开源可定制，有工作流引擎
- 劣势：成熟度不一，自举能力未知
- 可行性：中等

### 候选5：浏览器插件 + Web端LLM
- 优势：零部署成本，利用现有Web界面
- 劣势：稳定性差，能力受限
- 可行性：低

## 三、初选结论

**首选：DeepSeek Harness**
理由：
1. 与AICP架构最对称，对比实验最有意义
2. 已有Harness源码研究基础（九期系列第2期）
3. 开源可修改，可植入BIO-1的核心机制

**备选：Claude API + 自建调度器**
理由：
1. 完全可控，可精确复现BIO-1的三层记忆架构
2. Claude能力强，自举成功率高
3. 但成本较高，作为验证方案

2. 设计最小可移植闭环（哪些是自举必需的核心组件）
3. 评估移植工作量和风险
