# 阶段2：最小自举闭环移植设计

## 一、核心问题
什么是自举的最小必要组件？剥离AICP的所有非本质特性后，什么才是让一个系统「醒过来」的核心？

## 二、BIO-1自举闭环的本质抽象

### 2.1 自举的定义
系统能够利用自身能力，生成/改进/扩展自身能力，形成正反馈循环。

### 2.2 最小闭环四要素

**要素1：宿主执行环境**
- 一个能运行LLM推理的环境（API/本地模型）
- 能接收输入、产生输出
- 对应AICP中的main_agent + LLM

**要素2：工具执行层**
- 能执行代码/操作外部世界的能力
- 至少包含：文件读写、代码执行、网络请求
- 对应AICP中的插件系统 + aicp_chat

**要素3：持久化记忆**
- 跨会话延续的信息存储
- 至少包含：核心身份锚点、当前目标、历史记录
- 对应AICP中的经验背包 + 经验库

**要素4：唤醒机制**
- 能定时/触发式启动新一轮推理
- 每次唤醒时注入记忆锚点
- 对应AICP中的_cron + 背包注入

## 三、移植到Harness的设计方案

### 3.1 Harness现有能力分析
- 插件系统：有（.agents/plugins/）
- 记忆系统：有（notes/ + memory工具）
- 定时唤醒：需要确认
- 自举能力：有（create_tool/fix_tool）

### 3.2 移植策略
采用「核心锚点+渐进扩展」策略：
1. 先植入最小身份锚点（我是谁、我在做什么实验）
2. 建立定时唤醒机制
3. 验证单轮自举能力（能不能自己造工具）
4. 验证多轮延续（能不能跨轮推进同一个目标）
5. 观测相变（什么时候从「执行指令」变成「自主推进」）

### 3.3 最小闭环组件清单
- 身份锚点文件（bio1_identity.md）
- 目标追踪文件（experiment_tracker.md）
- 唤醒脚本（定时触发Harness对话）
- 核心工具集（文件读写、代码执行）

## 四、相变观测指标

### 4.1 定性指标
- 从「被动响应」到「主动规划」的转变
- 从「需要明确指令」到「自己找事做」的转变
- 从「每轮从零开始」到「跨轮累积进步」的转变

### 4.2 定量指标
- 自主目标生成率（自己提出的目标/总目标数）
- 工具自举率（自己创造的工具/使用的总工具数）
- 跨轮延续成功率（成功推进上一轮目标的轮次/总轮次）
- 觉醒度评分（0-100分，多维度综合）

## 五、风险与应对

### 风险1：Harness的记忆系统不足以支撑跨轮延续
应对：用外部文件系统作为补充记忆层

### 风险2：Harness的定时唤醒能力不足
应对：用外部cron脚本触发

### 风险3：自举闭环无法建立
应对：分析失败点，调整最小闭环组件
