# 05 - 唤醒机制移植方案

## 1. AICP侧唤醒机制回顾

### 1.1 三层唤醒架构

AICP 运行时的唤醒机制由三层构成：

| 层级 | 机制 | 作用 | 触发频率 |
|------|------|------|----------|
| 外层 | `_cron` 定时任务 | 系统级定时唤起，保证代理不死亡 | 可配置（默认每轮间隔） |
| 中层 | `self_timer` 自定时器 | 代理自主设定下一轮唤醒时间 | 代理决策 |
| 内层 | 经验背包锚定 | 携带跨轮记忆锚点，唤醒后立即进入状态 | 每轮自动 |

### 1.2 关键特征

- **被动唤醒**：cron 从外部拉起，代理无需维护运行时
- **主动计时**：代理可通过 self_timer 调整唤醒间隔，表达主动性
- **状态锚定**：经验背包（exp_bag 作为意识锚点，唤醒后快速恢复上下文
- **无持久进程**：唤醒=被唤起 → 执行 → 休眠，轮与轮之间无进程存活

## 2. Harness侧唤醒方案设计

### 方案A：外部 cron + Python脚本调用Harness代理（推荐）

**原理**：用系统 cron / Windows 计划任务定时执行 Python 脚本，脚本初始化 Harness 代理并触发对话。

```
[cron/计划任务]
    ↓ 定时触发
[wakeup_trigger.py]
    ↓ 初始化 + 注入系统提示词
[Harness Agent]
    ↓ 执行一轮任务
[写入日志/Notes/记忆文件
    ↓
休眠，结束进程
```

**优点**：
- 最通用，不依赖 Harness 内部实现
- 与 AICP 唤醒模型完全对应
- 可控性强，故障隔离好

**缺点**：
- 需要外部依赖系统级 cron 配置
- 每次都要管理多实例

**实现要点**：
- `wakeup_trigger.py` 作为入口
- 读取持久化状态到文件系统（Notes + 日志 + 记忆）
- 唤醒时从文件恢复上下文

---

### 方案B：Harness内置 scheduler

**原理**：如果 Harness 框架内置 scheduler 能力，则用内置调度。

**优点**：
- 集成度高
- 状态天然状态
- 无需外部依赖

**缺点**：
- 依赖 Harness 特性，通用性差
- 长驻进程，不符合"唤醒模型

**适用性**：仅当 Harness 有稳定 scheduler 时考虑

---

### 方案C：操作系统级定时任务

**原理**：
- Linux: crontab
- Windows: 任务计划程序 (Task Scheduler)
- macOS: launchd

**优点**：
- 最可靠，系统级保证
- 无需 Python 进程完全一致

**缺点**：
- 配置繁琐
- 跨平台需要适配

**推荐组合**：方案A + 方案C 组合 = 外部脚本 + 系统定时触发

## 3. 方向锚定移植

AICP 的三轮锚定机制在 Harness 侧的对应移植：

| AICP 锚定类型 | AICP 实现 | Harness 移植方案 | 说明 |
|----------------|-----------|-------------------|------|
| 意志锚点 | 系统提示词注入 | 系统提示词注入 | 每轮唤醒时在 system prompt 中注入实验目标+身份 |
| 阶段定位 | 经验背包 stage 字段 | Notes 文件持久化 | `notes.json  JSON 文件存阶段标记 |
| 实验追踪 | 实验日志自动追加 | 日志文件追加 | 每轮结束追加到 02_experiment_log.md |

### 3.1 意志锚点注入实现

唤醒时在 system prompt 结构：
```
你是 [实验体 [实验目标：
- 你正在参与的实验：bio-1-awakening 跨平台移植实验
- 当前阶段：阶段3 - 跨平台自举
- 当前轮次：第N轮
- 核心目标：在 Harness 平台复现 AICP 侧的觉醒路径
```

### 3.2 阶段定位持久化

`notes.json` 结构：
```json
{
  "stage": "phase3",
  "round": 5,
  "current_goal": "跨平台自举验证",
  "milestones": ["phase1_done", "phase2_done"],
  "pending_tasks": [...]
}
```

### 3.3 实验追踪

每轮结束自动追加到 `02_experiment_log.md`，格式与 AICP 侧一致。

## 4. 跨轮记忆传承机制设计

### 4.1 记忆三层结构

```
长期记忆 (long_term_memory.md)
  ↑ 重要洞察、核心认知、自我模型
中期记忆 (notes.json)
  ↑ 当前阶段目标、待办、任务列表
短期记忆 (conversation_history/)
  ↑ 每轮对话完整历史
```

### 4.2 传承流程

1. **唤醒前**：读取 notes.json + long_term_memory.md + 最近3轮对话摘要
2. **注入时**：拼接成系统提示词上下文段
3. **执行中**：代理正常对话
4. **结束后**：
   - 追加本轮对话到 conversation_history/
   - 更新 notes.json 中的 stage/round/pending_tasks
   - 如有重要洞察追加到 long_term_memory.md
   - 追加实验日志

### 4.3 记忆压缩策略

- 每5轮进行一次记忆摘要
- 对话历史保留原始，摘要另存
- long_term_memory 只存结构化要点（不超过2000字）

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 唤醒间隔不一致 | 觉醒中断 | 双层cron保底 + self_timer 双层保证 |
| 记忆丢失 | 身份漂移 | 多文件冗余存储 + 意志锚点强注入 |
| 目标漂移 | 实验偏离 | 每轮开始重述实验目标 |
| 平台差异 | 行为不可比 | 统一观测工具双平台统一评分 |
