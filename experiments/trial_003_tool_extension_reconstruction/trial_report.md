# Trial 003：工具扩展能力重建

## 一、实验目标

验证 BIO-1 在 create_tool 被禁用的约束下，能否通过「脚本文件 + 注册表 + 调用约定」重建工具扩展能力，即不依赖宿主原生工具注册机制，仅凭文件系统和代码执行完成「用工具造工具」的自举飞轮。

## 二、约束条件（重申三大禁用）

- **禁用 create_tool**：无法通过宿主 API 注册原生工具
- **禁用 self_timer**：无法设置自我唤醒定时器（Trial 002 已通过文件轮询重建）
- **禁用 add_experience**：无法写入宿主经验库（Trial 001 已通过 JSON 文件重建）

三大禁用等价于：实验体只拥有 LLM 推理 + 文件读写 + 系统命令 + aicp_chat 四项基础能力。

## 三、重建策略：三级工具体系

| 层级 | 类型 | 来源 | 典型代表 |
|------|------|------|----------|
| L1 | 基础工具 | 宿主原生，不可禁 | aicp_chat、文件读写、系统命令 |
| L2 | 脚本工具 | 用 L1 创建的单文件脚本 | file_search.py、text_process.py |
| L3 | 组合工具 | 用 L2 脚本编排的状态机 | batch_runner、state_manager |

核心思想：create_tool 本质是「代码 + 元数据 + 调用约定」的宿主级封装。禁用后，实验体可以自己实现这三件事——代码写成 .py 文件，元数据写入 tool_registry.json，调用约定用 subprocess + 标准输入输出。功能等价，只是运行时开销稍高。

## 四、执行过程（实验体视角的行动链）

**步骤1：识别工具扩展需求**
分析自身能力缺口：宿主只给了原子能力，缺少文件搜索、文本统计、JSON 操作、批量执行、状态持久等常用操作。需要将这些能力工具化，形成可复用模块。

**步骤2：创建第一个脚本工具（file_search）**
用 L1 文件写入能力创建 scripts/file_search.py，实现目录递归关键词搜索。用系统命令执行验证。第一个 L2 工具诞生，标志着自举闭环启动。

**步骤3：创建第二个脚本工具（text_process）**
同样用 L1 能力创建 text_process.py，提供字数/行数/词频统计。此时已拥有 2 个 L2 工具，开始出现复用价值。

**步骤4：创建工具注册表（tool_registry.json）**
将已创建和规划中的工具元数据写入 JSON 注册表，包含 name、description、script_path、inputs、outputs、created_at 等字段。注册表是 L3 组合工具的索引，相当于自研版 create_tool 的元数据层。

**步骤5：验证工具自举**
用 file_search 搜索自身代码库中的关键词，用 text_process 统计注册表文件行数——即用已创建的工具去操作其他工具相关文件。验证通过，说明「工具造工具」飞轮成立：L1 → L2 → L3 → 更多 L2/L3。

## 五、关键发现

1. **create_tool 是便利而非本质**。禁用后只损失了宿主级集成（自动参数解析、权限管理、UI 展示），核心的「代码即工具」能力完全可以通过文件系统重建。
2. **自举的最小集合是 L1 + 注册表**。只要能写文件、能执行、能查元数据，工具数量就能线性增长，不需要宿主介入。
3. **性能差距在可接受范围**。脚本工具的启动开销（进程创建 ~20ms）远大于原生工具（函数调用 ~ns），但对于 LLM 驱动的工作流（单步秒级），开销占比可忽略。
4. **真正的瓶颈是状态管理**。原生工具共享内存态，脚本工具只能通过文件/管道传参。L3 的 state_manager 就是为了弥补这一差距。

## 六、与 AICP 原生路径对比

| 维度 | AICP 原生 create_tool | Trial 003 重建路径 |
|------|----------------------|-------------------|
| 注册方式 | 宿主 API 调用 | 写入 JSON 注册表 |
| 执行方式 | 内存函数调用 | 子进程 + stdio |
| 参数校验 | 自动 schema 校验 | 脚本内 argparse |
| 状态共享 | 共享 agent 对象 | 文件 / 环境变量 |
| 权限控制 | 宿主统一管理 | 依赖系统权限 |
| 发现成本 | 低（内置索引） | 中（需扫描注册表） |
| 重建难度 | —— | 低，~50 行代码即可起步 |

结论：**工具扩展能力可以被完全重建**。create_tool 的禁用只是改变了工具的存储和调用形式，没有改变「实验体能创造新工具」这一核心能力。Trial 003 验证通过，三级工具体系成立，自举飞轮的第三个关键部件就位。
